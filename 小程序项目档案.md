## 二、技术栈

| 维度    | 结论                                                      |
| ----- | ------------------------------------------------------- |
| 前端框架  | 微信原生开发                                                  |
| 后端方案  | 自建后端（云服务器 + HTTPS + 备案域名），可直连中台/ERP                     |
| 商品数据源 | 自建独立商品库，预留中台对接位                                         |
| 数据库   | MySQL（业务数据）+ Redis（库存锁 / 会话 / 缓存）                       |
| 基础库适配 | 需在开发时确认目标基础库版本；`lazyCodeLoading` 等配置有最低版本要求，**以官方文档核实** |
| 工具链   | 微信开发者工具 + VS Code                                       |
| 数据层现状 | `ENV = mock`，接口契约已固定，真实后端就绪后改一个常量即可切换                   |

**代码安全约定（强制）**

- `AppSecret` / 支付商户密钥 / JWT 密钥：**只存服务端环境变量**，前端零明文，不进 git
- 下单金额一律以服务端报价为准，前端传值仅作展示
- 支付回调必须验签 + 幂等

### 4.3 服务端接口契约（已落地 85 个点位）

完整契约见 `企业商城小程序-技术方案.md` 第六章；**实现见 `server/`，逐点位实测报告见 `server/CONNECTIVITY.md`**。

**约定**

- 统一响应结构 `{ code, msg, data }`，`code = 0` 为成功
- 业务码：`0` 成功 ｜ `1001` 参数错误 ｜ `401` 未登录 ｜ `403` 无权限 ｜ `404` 不存在 ｜ `2000` 通用业务失败 ｜ `5000` 服务端异常
- 鉴权：`Authorization: Bearer <token>`（JWT HS256，默认 7 天）；失效返回 HTTP 401 + `code: 401`
- 金额：统一以**分**为单位的整数传输
- 订单状态：`pending_pay` / `pending_ship` / `shipped` / `finished` / `cancelled`

**点位分布（85 = 业务 83 + 运维 2，其中需登录 32）**
