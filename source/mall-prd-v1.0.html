本清单用于新建品牌小程序商城的需求评审与开发报价，是可直接交付研发与外部供应商的功能边界文档。清单按「品牌自营商城 + 会员营销」定位，在原始拆解版（43 条需求、10 大业务域、452 个页面）基础上大幅删减，最终收敛为 33 条功能、7 个模块，其中一期必做的 P0 功能 14 条，可先跑通「选品 → 下单 → 支付 → 售后」的完整交易闭环。

一、文档说明

本章说明本清单的编制目的、优先级判定标准，以及相对原始拆解版的删减范围。

（一）编制目的

本清单用于新建品牌小程序商城的需求评审与开发报价，是可直接交付研发与外部供应商的功能边界文档。本版在原始拆解版（43 条需求、10 大业务域、452 个页面）基础上，按「品牌自营商城 + 会员营销」的实际经营需要做了大幅删减，最终收敛为 33 条功能、7 个模块。

（二）优先级定义

优先级含义判定标准
P0一期必做缺失即交易链路中断，商城无法开张
P1二期建议影响转化与复购，是会员营销的核心抓手
P2三期可选体验增强或低频玩法，可按预算后置

（三）本版删减范围

相对 V2.1 全量拆解版，本版的取舍如下。

原模块处理原因
首页装修、商品、购物车、交易支付、订单售后保留（精简条目）商城交易主干
会员卡、等级权益、权益卡礼品卡保留会员营销核心
优惠券、积分商城、签到任务保留会员营销核心
拼团、砍价助力保留（定为 P1）拉新裂变需要
连锁门店、门店货架、门店自提、扫码购删除本期不做线下 O2O
分销员、导购工作台、社区团购删除无分销体系
小程序直播、视频号带货删除直播走独立直播间，商城不做挂载
抽奖、盲盒、摇一摇、集卡、预约报名降为 P2 可选低频玩法，按需保留
有赞 SaaS 底座、分包体积、加密解密等技术细节删除属拆解过程数据，非需求
模板自带但未启用模块（教育、酒店、品酒会等）删除与自身业务无关

二、产品定位与目标

本章界定商城的定位、经营目标与核心用户场景，作为后续功能取舍的依据。

（一）产品定位

一句话定位：品牌官方自营小程序商城，覆盖「整机销售 + 耗材复购 + 会员运营」的完整闭环。

（二）产品目标

目标层级目标描述衡量指标
业务目标承接投放、内容与私域流量的直接成交GMV、支付转化率、客单价
用户目标一站完成选购、复购、会员权益领取复购率、会员数、7 日留存
品牌目标沉淀品牌私域阵地与会员资产会员开卡数、私域留存

（三）核心用户与场景

用户群核心诉求对应场景
品牌会员 / 老客耗材复购、会员价、积分兑换从「我的」进订单与积分商城复购
广告与内容引流用户快速了解并下单主推款落地页 → 商品详情 → 下单
新客 / 泛人群领券试买、拼团低价领券中心 → 拼团下单

五、非功能需求

类别要求
性能高频链路做分包预加载（购物车、下单、支付结果、个人中心）；首页依赖远程装修数据，需骨架屏与加载失败兜底
包体管理主包与单个分包均需控制在微信平台上限内；新增功能优先落入既有分包，避免主包膨胀
隐私合规若使用定位能力须在隐私协议中明示并前置授权；按《个人信息保护法》与微信隐私接口规范留存授权记录
安全风控支付走微信支付官方通道；会员、积分、券等资产类数据须服务端校验；签到、领券、抽奖接口需限频防刷
可运营性首页装修、活动、优惠券、会员权益均需后台可配置，配置变更不触发小程序重新发版
稳定性下单、支付、退款关键链路需具备异常兜底与订单状态补偿机制

六、分期建设建议

阶段建设内容目标
一期（MVP）全部 14 条 P0 功能商城可开张交易，完成「选品 → 下单 → 支付 → 售后」闭环
二期全部 13 条 P1 功能会员营销体系上线，拉动复购与裂变
