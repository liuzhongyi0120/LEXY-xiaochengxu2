# 微信开发者工具「模拟器启动失败」排障手册

> 首次记录 **2026-10-15**（工具版本 Stable 2.02.26020080）。
> **这是开发者工具自身的进程/环境层故障，不是本项目的小程序代码问题** —— 判据见第一节。

---

## 一、5 秒定性：先看日志「走到哪一步才失败」

日志位置（`<hash>` 由工具自己生成，本机是 `881c4ce5e2aa53e364dbbb2e9b50c528`）：

```
%LOCALAPPDATA%\微信开发者工具\User Data\<hash>\WeappLog\logs\<最新时间戳>.log
```

| 日志里最后走到 | 含义 | 责任层 |
|---|---|---|
| 没有 `[SimulatorService] simulator app compile` | 编译没过 | **我们的代码** → 去看编译报错 |
| `app compile` 过了，但 `createSimulator` 之后**几毫秒**就 `simulator launch failed` | 工具连模拟器进程都没起 | **工具/系统环境** ← 2026-10-15 这次 |
| 编译通过且模拟器起来了，只是**页面空白** | 是真机渲染/数据问题 | 我们的代码 → 用第三节的自证手段定位 |

判据原文（本次）：

```
15:45:19.476  [SimulatorHttpService] Create server success 63212     ← 模拟器服务端起来了
15:45:21.972  [BuilderFactory] createBuilder builder.ready() done    ← 编译器就绪
15:45:24.047  [SimulatorService] simulator app compile               ← 编译通过
15:45:24.588  [SimulatorService] [simulator] createSimulator s0
15:45:24.595  [appservice] simulator launch catch error Error: simulator launch failed   ← 7ms 后失败
```

`createSimulator` → 失败只隔 **7 毫秒**：连"启动进程"这一步都没走到，是工具自己放弃。

## 二、按序执行，成功即停

| # | 动作 | 说明 |
|---|---|---|
| 1 | **完全退出工具再重开** | 确认任务管理器里 `微信开发者工具.exe` **一个不剩**。Electron 系应用常有"窗口关了进程还在" |
| 2 | **清掉本机其它 Chromium 系进程** | 本仓库做 UI 验收会起无头 Chrome（`.tooling/_cdp-headless.mjs` + `chrome-headless-shell`）。它们与工具**同时活跃时**曾是时间上重叠的可疑干扰（2026-10-15 那天就是）。清掉：`node .tooling/_procs.mjs` 找到 PID → `node .tooling/_kill.mjs <pid>`；跑完 UI 测试也该主动清 |
| 3 | **清模拟器缓存** | 关掉工具后，把 `<User Data>\<hash>\WeappSimulator\WeappFileSystem`、`WeappStorage`、`WeappBackgroudData` 三个子目录改名（**改名而不是删除**，保留回退）；或删 `WeappCache\WeappSimualtorSdkApiTransferData` |
| 4 | **重启电脑** | 清 Windows 上未释放的句柄/共享内存 |
| 5 | **更新或重装工具** | 用最新稳定版覆盖安装；安装在非系统盘（本机在 `E:\微信开发者工具\`）不影响结论 |

## 三、怎么自证「不是我们代码的问题」（本机可一键跑）

```bash
# 1) 全量门禁（含小程序端渲染、点位、契约）
node server/tools/check-all.mjs                  # 期望 634/634，exit 0

# 2) 装修台逐页量测：18 个页面逐个打开编辑器，量三栏几何
node .tooling/_probe-editor-pages.mjs            # 期望「全部 18 个页面的三栏都有内容」

# 3) 真机源码预览（编译 miniprogram/ 源码，不是第二份近似 HTML）
#    浏览器开 http://127.0.0.1:3000/preview?page=home
#    期望：手机壳 375×718、图片 0 破图
```

> `_probe-editor-pages.mjs` 是「什么都不显示」类问题的**通用分诊工具**，覆盖五种落点：
> 左栏组件面板空 / 手机壳 0 高 / 右栏属性面板空 / 整页白屏 / `/preview` 空。
> 判据全部落在 `getBoundingClientRect` 与 `innerText` 上（缩略图上判空必错）。

## 五、⚠️ 另一种「看不到东西」：模拟器**能启动**，但页面/素材全不显示

> 2026-10-15 补充。**这和上面的 `simulator launch failed` 是两回事**，别往第一节的方向查 ——
> 日志里 `simulator app compile` 是通过的、模拟器也确实起来了，纯粹是**画面里没内容**。
> 本机实测踩到的那一种是：**后端地址连不上**（公司出口按 SNI 拦域名）。

### 5.1 先分清是哪种「空」

| 现象 | 大概率是 |
|---|---|
| 整页空白，只剩导航栏 + tabBar | **素材全挂**（图片/视频加载失败）—— 该页区块若全是图片，就会整页空白 |
| 有文字、没图片 | 同上，只是这页有文字区块撑着 |
| 报「请求失败 / 网络错误」 | `BASE_URL` 连不上（见 5.2） |
| 页面白 + 控制台有 JS 报错 | 这才是代码问题 → 跑门禁自证（第三节） |

⚠️ 首页那 11 个区块**全是图片/视频、一个文字区块都没有**，所以「素材全挂」在首页上的表现
就是**整页空白**，非常容易误判成「小程序坏了」。

### 5.2 本机这条链路的高频原因：公司出口按 SNI 拦 `mall.lexy.cn`

分层自证（本机）：

```bash
node -e "
const net=require('net'), tls=require('tls');
const IP='14.103.50.137';
net.connect(443,IP).on('connect',()=>{console.log('TCP 443 ✓ 连上了');}).on('error',e=>console.log('TCP ✗',e.code));
setTimeout(()=>tls.connect({host:IP,port:443,servername:'mall.lexy.cn',rejectUnauthorized:false})
  .on('secureConnect',()=>console.log('TLS ✓ 证书:',(this.getPeerCertificate()||{}).subject))
  .on('error',e=>console.log('TLS ✗',e.code||e.message)),800);
"
```

判读：

```
DNS 解析 mall.lexy.cn         ✓ → 14.103.50.137
TCP 443 裸 IP                 ✓ 20ms 连上
TLS 握手（SNI=mall.lexy.cn）   ✗ ECONNRESET 43ms      ← TCP 通、一带 hostname 握手就被 RST
```

→ 这是**出口设备按 SNI 过滤**的典型特征。**改 hosts / 换 DNS 都无效**（DNS 早就通了），
处置与现状见 `deploy/添加子域名操作单.md` **第六之二节**。
**代码层已根治**：开发者工具的模拟器现在按运行环境自动走本机 `http://127.0.0.1:3000`，
只有命令行工具要抓线上数据时才还需要应急。

### 5.3 三项前置，缺一个都会「全空」

1. **本机后端在跑**（模拟器走的就是它）：
   `cd <仓库根> && DEBUG_PAGE=on ADMIN_PAGE=on node server/index.js`
2. **开发者工具勾了**「不校验合法域名、web-view、TLS 版本以及 HTTPS 证书」
   （模拟器走 `http://127.0.0.1:3000`，既非 HTTPS、也非备案域名）——已由
   `project.config.json` 的 `setting.urlCheck: false` 落盘
3. **素材文件实际在位**：`server/data/uploads/` 下确实有文件

一键自检（本机）：

```bash
# ① 后端在监听 3000
node .tooling/_procs.mjs | grep 3000

# ② 素材链路通不通（取 replica 里引用的第一个素材，期望 HTTP 200）
node -e "
const r=require('./miniprogram/config/replica.js');
const u=r.HOME_BLOCKS[0].images[0].image;
fetch('http://127.0.0.1:3000'+u).then(x=>console.log(u,'→',x.status,x.headers.get('content-type')));
"

# ③ 运行档位选得对不对（13 个环境逐个试，真机必须恒为 server）
node .tooling/_verify-env-auto.cjs
```
