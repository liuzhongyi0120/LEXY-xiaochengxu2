# 微信支付接入清单 —— 「申请成功」≠「能收款」

> 对应《微信上传前检查清单.md》阻塞项 **②**。
> 生成日期：2026-10-14　·　结论：**本项目目前没有任何商户号接入**，且代码里的真实支付**还没写**。
> 本文分两半：**上半 = 你（在后台）要办的**；**下半 = 我（在代码里）要办的**。

---

## 一、申请状态在哪里看（我这边看不到）

商户号申请状态只在**你的账号**里可见，任何脚本/API 都查不到（需要商户凭据）。按可靠度看这三处：

| # | 位置 | 你能看到什么 |
|---|---|---|
| 1 | **mp.weixin.qq.com** → 左侧**「微信支付」**（旧版后台在「功能 → 微信支付」） | **最权威**。这一页直接显示：还没申请 / 审核中 / 已开通（带商户号）/ 已驳回 |
| 2 | **pay.weixin.qq.com**（微信支付商户平台） | 能用商户号或管理员微信扫码**登录进去** = 账号已开通 |
| 3 | 手机：**「微信支付」公众号**消息 + **短信** | 开通/审核通知；部分环节会要求**法人人脸核身或短信核验** |

### 状态判读

| 后台显示 | 含义 | 下一步 |
|---|---|---|
| 「**申请微信支付**」按钮（可点） | **还没申请** | 点进去填：主体用**绿能科技执照**、结算用**同名对公账户** |
| 「**审核中** / 待审核」 | 已提交，等 | 1~5 工作日；让法人留意电话/短信，漏接会拖慢 |
| **10 位商户号** +「已开通 / 正常」 | ✅ **申请成功** | 去商户平台做「绑定 AppID」+ 取密钥（第四节） |
| 「**审核不通过**」+ 原因 | 被驳回 | 按原因改后重提 |

### 驳回高频原因（先自查，省一轮）

1. **对公账户名 ≠ 主体名** —— 账户名必须逐字等于「莱克电气绿能科技（苏州）有限公司」（括号全半角、有无「（苏州）」都要一致）
2. **执照经营范围不含零售/销售** —— 缺就先去市监增经营范围
3. **主体类型/证件类型选错**（企业 vs 个体工商户）
4. **结算银行卡不是对公账户**，或开户行填错
5. 类目需资质（家用电器零售一般**不需要**额外资质，这也是我们选「商家自营」的原因）

> ℹ️ 微信认证 ✅ 已完成 —— 它是**申请支付的前提**，现在具备条件。

## 三、⚠️ 更重要的发现：真实支付在这个项目里**还没写**

`server/lib/wechat.js` 里有**三处空壳**：

| 位置 | 内容 | 后果 |
|---|---|---|
| `unifiedOrder()` **L99** | `throw new Error('微信支付 v3 证书未配置：请设置 WX_MCH_CERT 与 WX_MCH_KEY_PATH 后再启用')` | 真实模式下**下单直接抛异常** |
| `buildPayParams(prepayId, real)` **L113** | real 分支 `paySign: ''`（**没做 RSA 签名**） | 参数喂给 `wx.requestPayment` 必然失败 |
| `verifyNotifySignature()` **L128** | `return !HAS_WX_PAY` | 真实模式下**恒返回 false → 回调一律 403** |

（顺带说明：`WX_MCH_CERT` / `WX_MCH_KEY_PATH` 这两个变量名虽然在报错里出现，但**代码里根本没有读它们的地方** —— 那只是一句「未实现」的占位提示。）

### ⛔ 所以：**别急着往 `.env` 填 `WX_MCH_ID` / `WX_PAY_KEY`**

填了之后会发生什么：

1. `/api/health` 变 `pay: "real"` —— **看着像好了，其实什么都没有**
2. 下单接口从「返回沙箱参数」变成 **500 报错**
3. 前端 `sandbox` 字段变 `false` → 「模拟支付成功」入口**自动消失** → **用户彻底付不了款**
4. 更糟的组合：`.env` 里 `ALLOW_MOCK_PAY=1` 仍在 → 后端 `POST /api/pay/mock-success` **依然开放**，可被直接调用把订单标记成已支付（白嫖）

**正确顺序：申请通过 → 取密钥 → 我实现 v3（下单 + 签名 + 回调解密）→ 最后才填 `.env`。**
在那之前，`.env` 保持原样，模拟支付链路是好的（可继续联调）。

## 四、申请通过后，从商户平台取这四样给我

> ⚠️ 都是**凭据**，不要在公开渠道发；给我时我会直接写进服务器 `.env`（不进 Git）。

| # | 名称 | 在哪取 | 用途 |
|---|---|---|---|
| 1 | **商户号 mchid**（10 位数字） | 商户平台首页 / 账户中心 | `WX_MCH_ID` |
| 2 | **APIv3 密钥**（32 位） | 账户中心 → **API 安全** → 设置 APIv3 密钥 | 回调 AES-256-GCM 解密 + 拉平台证书 |
| 3 | **商户 API 私钥** `apiclient_key.pem` | 账户中心 → API 安全 → **申请 API 证书**（用官方工具生成，**只此一次下载机会**，丢了要重签） | 请求签名（RSA-SHA256） |
| 4 | **证书序列号** | 申请页会显示；或用 `openssl x509 -in apiclient_cert.pem -noout -serial` 取 | 签名串里的 `serial_no` |

> 平台证书（用于验回调）**不用你手动下载** —— v3 有官方机制 `GET /v3/certificates`，用 APIv3 密钥解密获取，我在代码里自动拉取并缓存。

## 六、我这边要写的代码（约三块）

1. **v3 JSAPI 下单**：`POST https://api.mch.weixin.qq.com/v3/pay/transactions/jsapi`，用商户私钥 RSA-SHA256 签名（构造 `method\nurl\ntimestamp\nnonce\nbody\n` 签名串），返回 `prepay_id`
2. **小程序端支付参数签名**：`paySign = RSA-SHA256(appId\ntimeStamp\nnonceStr\npackage\n)` —— 替换现在的空串占位
3. **回调**：AES-256-GCM 解密 `resource`（用 APIv3 密钥）→ 校验 `transaction_id / out_trade_no / amount` → 复用现有 `orderLib.markPaid()`（**这部分逻辑已存在且有测试**，只需换验签与解密层）+ 平台证书验签

> 支付结果页、订单状态流转、退款入口这些**都已实现**，只是走的是模拟分支。所以工作量集中在上面三块。

## 八、验收标准（不接受「配置看起来对」）

1. 真机 → 商品 → 下单 → **拉起收银台** → 实付最小金额
2. 支付成功页 → 订单状态变「待发货」
3. 商户平台「交易中心」能看到该笔流水
4. 服务器日志**无回调 403**；订单在**未手动干预**的情况下变已支付
5. 前端**不再出现**「模拟支付成功」按钮；直接 `POST /api/pay/mock-success` 应返回 **403**
