# 域名上线手册 —— 解决「微信不接受 IP」这一条

> 对应《微信上传前检查清单.md》**阻塞项 ①**。本机体检脚本 `node .tooling/preflight-wechat.mjs`
> 每次都会把这条判红，直到地址变成**已备案域名**为止。

## 一、为什么非改不可（30 秒版）

| 事实 | 后果 |
|---|---|
| 现在 `constants.js` 里是 `https://14.103.50.137/mall-api`，**IP 不是域名** | 微信「服务器域名」**只收域名**，填 IP 直接不让保存 |
| 开发者工具有「不校验合法域名」开关，能跑 | 那只是**本地特权**；**正式版真机、以及审核环境一律校验** |
| 真机临时绕过：胶囊 →「开发调试」→ 打开 | 只有**你自己**的体验版能这样；审核员不会开，用户更不会 |
| 结论 | **不改 = 审核阶段必挂**（接口全失败，页面全空） |

## 二、三条路径（推荐第一条）

| | 路径 | 要做什么 | 大概耗时 | 成本 |
|---|---|---|---|---|
| ⭐ **A** | **借公司已备案的 `lexy.cn` 加个子域**（如 `mall.lexy.cn`） | 加一条 A 记录 + （合规上）提交接入备案 | **解析今天就能通**；接入备案初审通过即合规 | 0 |
| B | 新买一个域名，从零备案 | 买域名 → 首次备案（主体证件 + 法人核验 + 管局审核） | **1~20 个工作日** | 域名 ~35 元/年 |
| C | 后端迁到**中国香港**服务器，域名免备案 | 迁站 + 换 IP + 重配 | 1~2 天 | 香港轻量 ~24 元/月 |

> 为什么推荐 A：`lexy.cn` 是公司官网主域名，**必然已有 ICP 备案号**。
> 腾讯云官方口径（2025-04 文档）：
> - 「若顶级域名在腾讯云已有备案，则对应的**二级域名无需再备案**」
> - 「若原备案接入商非腾讯云，您需在腾讯云提交**转入（接入）备案**申请……**初审通过以后则不影响您的网站访问**」
>
> 实测 `lexy.cn` 的 NS 是 `ns1/ns2.ename.net`（**易名中国**），官网 A 记录指向 `221.231.47.x / 180.97.x`
> —— 也就是说**备案接入商多半不是腾讯云** → 走「接入备案」分支，**初审过了就能用**，比首次备案快很多。

> 路径 C 的取舍：香港服务器不用备案，**微信也确实只校验「域名有没有备案号」、不探测服务器位置**，
> 所以 `shop.lexy.cn` 解析到香港也能配上去。但它**违背备案的属地要求**，且数据库/素材都在上海这台机器上，
> 迁移成本不小 —— 仅当 A、B 都被卡死时再考虑。

## 三、谁做什么（分工表）

| # | 谁 | 做什么 | 具体在哪做 |
|---|---|---|---|
| 1 | **你** | 决定子域名叫什么（建议 `mall.lexy.cn`，也可 `shop` / `api` / `wx`） | —— |
| 2 | **IT / 网络组** | 加一条 **A 记录**：`mall.lexy.cn` → `14.103.50.137` | 易名中国（ename）控制台；`lexy.cn` 的解析权在他们手里 |
| 3 | **你 / IT** | 在腾讯云备案控制台搜 `lexy.cn`，看接入商是不是腾讯云；不是就提交**接入备案**（要一台腾讯云资源，这台 CVM 正好符合） | 腾讯云 → 备案 → 新增接入 |
| 4 | **我（脚本）** | 服务器侧：签证书 + 挂 443 反代 | `deploy/enable-domain-https.sh`，一条命令 |
| 5 | **我（脚本）** | 小程序侧改地址 + 复体检 | `.tooling/switch-env.mjs`，一条命令 |
| 6 | **你** | 微信公众平台配 `request 合法域名` | 开发管理 → 开发设置 → 服务器域名 |

> 弹性 IP `14.103.50.137` 是**固定**的（2031-06 到期），不会因为重启换 IP，所以 A 记录指向它很稳。

## 四、动手：三步，每步都能单独回滚

### 步骤 1（IT 加解析 → 你验证）

在易名中国控制台加完 A 记录后，**本机**验证生效（不是猜，是真查）：

```bash
node -e "require('dns').promises.resolve4('mall.lexy.cn').then(a=>console.log(a))"
# 期望输出包含 14.103.50.137
```

解析没生效就**别往下走** —— 下一步的脚本会自己拦下来（它拿不准就退出，不猜）。

### 步骤 2（服务器侧，一条命令）

```bash
# 把脚本传上去（本机执行）
scp deploy/enable-domain-https.sh root@14.103.50.137:/opt/lexy-mall/deploy/
# 服务器执行
ssh root@14.103.50.137 'DOMAIN=mall.lexy.cn bash /opt/lexy-mall/deploy/enable-domain-https.sh'
```

它做三件事，**每件都不碰同机别人的配置**：

1. 建 `/var/www/lexy-acme` + 80 端口 server 块 → 给 Let's Encrypt 做 HTTP-01 校验
2. `certbot certonly --webroot` 签一张**该域名**的证书
   （**绝不碰** 443 上那张 `14.103.50.137` 的 IP 证书，也不动 `stopwatch-cert-renew.timer`）
3. 建 443 server 块 → 直接反代 `127.0.0.1:3000`，自带 `client_max_body_size 60m`

结尾会跑三个本机探针（`--resolve` 方式，**绕开公网 DNS 缓存**，签名完立刻能验）：
健康接口 JSON、证书里的 SAN 域名、上传目录可连通。

**回滚只要一条**（IP 链路全程没动，随时切回）：

```bash
rm -f /etc/nginx/sites-enabled/lexy-mall-domain-80 /etc/nginx/sites-enabled/lexy-mall-domain-443 \
  && nginx -t && systemctl reload nginx
```

### 步骤 3（小程序侧，一条命令）

```bash
node .tooling/switch-env.mjs --url=https://mall.lexy.cn/mall-api
```

脚本会改 **两处**（`BASE_URL_MAP` 的值 + 文件头注释里那句旧 IP），改完 `require` 回来核对一遍才收工。
它有三个守卫：**传 IP 直接拒**、**漏 `/mall-api` 直接拒**、**非 https 直接拒** —— 免得写进一个必然被微信拒的地址。

然后复体检：

```bash
node .tooling/preflight-wechat.mjs     # 阻塞项应该少掉「IP」这一条
node server/tools/check-all.mjs        # 门禁（有断言依赖 BASE_URL）
```

最后在**微信公众平台**配一次（全局只此一处）：

> 开发管理 → 开发设置 → 服务器域名 → **request 合法域名** → 新增 `https://mall.lexy.cn`

> `downloadFile` **不用配**：小程序端所有图片走 `<image src>` 标签，源码里零 `wx.downloadFile`。
> （若以后加了「下载素材到本地相册」之类的功能，再回来加。）

## 五、怎么确认「真的通了」（别只看脚本说 OK）

| 检查 | 怎么查 | 期望 |
|---|---|---|
| 本机（绕 DNS） | 脚本末尾自动跑 | 健康接口返回 JSON |
| 公网解析 | 手机浏览器打开 `https://mall.lexy.cn/mall-api/api/health`（**用 4G，别用公司 WiFi**） | 同上，且地址栏是锁 |
| 证书链 | 浏览器点锁图标 | 颁发者 Let's Encrypt，域名对得上 |
| 备案 | 工信部 `beian.miit.gov.cn` 查 `lexy.cn` | 有备案号 |
| 小程序 | 开发者工具**关掉**「不校验合法域名」→ 编译 | 首页商品正常出图、接口不报错 |
| 真机 | 上传体验版，手机打开 | 同上（这一步才是最终判据） |

## 六、时间线（并行推进）

```
今天    ├─ 你：定子域名 → 发 IT 加 A 记录
        ├─ 你/IT：腾讯云备案控制台提交「接入备案」（需要主体证件；这台 CVM 就是可备案资源）
        └─ 解析一生效 → 我跑步骤 2 + 3 → 域名链路当天可用
D+1~3   └─ 接入备案初审通过（腾讯云口径：初审通过即可正常解析使用）
提审前  └─ 备案 ① + 支付 ② + 隐私申报 ③ + 小程序备案 ④ + 微信认证 ⑤ 全部到位 → 再跑 preflight 看到「阻塞 0 项」
```

## 七、常见卡点

| 现象 | 原因 | 处理 |
|---|---|---|
| 脚本报「没解析到本机」 | A 记录没加 / 没生效 / 加了 AAAA | 等 1~10 分钟；确认加的是 `mall` 这个**主机名**的 **A** 记录 |
| `certbot` 报 HTTP-01 失败 | 80 端口公网不可达 | 腾讯云安全组放行 **80**（443 已在用，说明只差 80）；确认 80 没被别的规则拦 |
| 浏览器能开、微信配不上 | 域名没备案 / 证书不被信任 | 查备案号；确认走的是 443 而不是自签证书 |
| 配上去后接口 404 | `BASE_URL` 漏了 `/mall-api` | 用 `switch-env.mjs` 重设，它强制要求该后缀 |
| 上传大图 413 | nginx 的 `client_max_body_size` 没放开 | 脚本已写 60m；若手工改过配置，确认三处同向（见铁律 11~14） |
