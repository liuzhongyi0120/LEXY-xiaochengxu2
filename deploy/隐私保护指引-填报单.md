## 四、✅ 代码侧**不需要**改：微信有官方兜底弹窗

> **⚠️ 2026-10-16 自我纠正：本节此前写「不补弹窗 → 真机功能直接失效」，这是错的，已撤回。**

查微信官方《小程序隐私协议开发指南》**第六节「官方隐私弹窗功能说明」**原文：

> 平台还提供了官方隐私授权弹窗。此弹窗在隐私相关功能启用后……**无需开发者适配开发，自动向 C 端用户展示**。
> 当开发者调用隐私相关接口时，微信会判断此次调用是否需要触发 `wx.onNeedPrivacyAuthorization` 事件，
> **若触发后开发者未进行响应，微信将主动弹出官方弹窗**。若用户同意，该接口将正常执行后续调用逻辑。

⇒ 本项目**不做任何代码改动**，剪切板 / 手机号 / 昵称头像也都能正常授权使用。
（2023-10-17 起「隐私相关功能一律启用」—— `__usePrivacyCheck__` 已不再是总开关。
项目里确实没有 `wx.getPrivacySetting` 等实现，但那只等于「没做自定义弹窗」。）

**两条仍需注意的边界**：

1. **`<input type="nickname">` 在用户未同意时不会触发隐私事件，而是降级成普通 `<input type="text">`**（官方原文）。
   不影响商城功能可用；只有很在意昵称控件时才需要自定义弹窗。
2. 🔥 **提审时绝不能勾「未采集隐私」** —— 官方错误码说明：
   `A:fail appid privacy api banned` = 「开发者在 mp 提审时勾选了『未采集隐私』……**被平台回收了接口调用权限**」。

**若日后要做自定义弹窗**（纯体验优化，非必需）：`wx.getPrivacySetting` 判 `needAuthorization` → 弹窗 →
`<button open-type="agreePrivacyAuthorization">` + `bindagreeprivacyauthorization` 回调。

**另**：官方说明「补充的隐私类型声明，将在 **5 分钟后生效**」—— 刚提交完立即真机测试，会误判成"没生效"。
